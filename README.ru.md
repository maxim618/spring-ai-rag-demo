# Spring AI RAG Demo

![Java 21](https://img.shields.io/badge/Java-21-ED8B00?logo=openjdk&logoColor=white)
![Spring Boot](https://img.shields.io/badge/Spring%20Boot-4.1.0-6DB33F?logo=springboot&logoColor=white)
![Spring AI](https://img.shields.io/badge/Spring%20AI-2.0.0-6DB33F?logo=spring&logoColor=white)
![Maven](https://img.shields.io/badge/Maven-3.9.9-C71A36?logo=apachemaven&logoColor=white)

Учебный проект для изучения **Spring AI 2.0** и построения приложения на основе
**Retrieval-Augmented Generation (RAG)** с практическим бизнес-сценарием.

Проект развивается постепенно: от базовой интеграции с LLM к RAG-конвейеру,
который сможет работать с внутренними документами компании и формировать ответы
на основе релевантных фрагментов исходных материалов.

## Практический сценарий

В качестве целевого сценария рассматривается компания по доставке еды, в которой
работает около 250 курьеров.

Перед началом смены каждый курьер в обязательном порядке проходит check-list для
повторения стандартов доставки.

Стандарты хранятся во внутренних документах компании. Идея проекта заключается
в том, чтобы сделать эти знания более доступными во время процесса подготовки
к смене с помощью RAG-ассистента.

Предполагается, что ассистент сможет:

- находить релевантные части стандартов доставки;
- отвечать на вопросы курьера, используя стандарты в качестве контекста;
- объяснять применимый стандарт в конкретной ситуации;
- помогать в подготовке к обязательному check-list;
- формировать ответы на основе актуальной документации компании, а не только
  общих знаний LLM.

Проект не предполагает замену обязательного check-list. Цель — исследовать,
как RAG может сделать специализированную базу знаний более доступной и полезной
в реальном операционном процессе.

## Почему RAG?

Обычная LLM не знает внутренних стандартов конкретной компании и не должна
надёжно воспроизводить их по памяти.

RAG позволяет разделить две ответственности:

- **Документы компании** являются источником предметно-специфических знаний.
- **LLM** понимает вопрос и формирует естественный ответ, используя найденный
  контекст.

Поэтому сценарий обучения курьеров является практическим примером применения
RAG к частной, специализированной и изменяемой информации.

## Текущий статус

Проект находится на ранней стадии разработки.

Реализовано:

- базовое приложение на Spring Boot;
- интеграция со Spring AI;
- настройка `ChatClient`;
- интеграция с OpenAI-совместимым API;
- простой chat endpoint.

Планируется:

- загрузка документов (Document Ingestion);
- разбиение документов на части (Document Chunking);
- генерация эмбеддингов (Embeddings);
- подключение векторного хранилища (Vector Store);
- поиск релевантных документов (Retrieval);
- дополнение prompt на основе найденного контекста;
- подготовка документов со стандартами доставки;
- сборка сквозного RAG-конвейера;
- тесты компонентов RAG.

## Архитектура

Целевой RAG workflow:

```text
Стандарты компании
       │
       ▼
Загрузка документов
       │
       ▼
Разбиение документов
       │
       ▼
   Embeddings
       │
       ▼
Векторное хранилище
       │
       │ релевантный контекст
       ▼
Вопрос курьера
       │
       ▼
    Retrieval
       │
       ▼
Релевантные документы
       │
       ▼
      LLM
       │
       ▼
     Ответ
```

На текущем этапе компоненты retrieval и vector store ещё не реализованы.

## Конфигурация

Приложение использует OpenAI-интеграцию Spring AI и может работать с
OpenAI-совместимым API.

API-ключи должны передаваться через переменные окружения и не должны храниться
в репозитории.

Пример:

```bash
export OPENAI_API_KEY=your-api-key
```

Настройки провайдера и модели находятся в `application.properties`.

## Запуск приложения

### Требования

- Java 21
- Maven 3.9+
- API-ключ OpenAI-совместимого провайдера

### Запуск

```bash
mvn spring-boot:run
```

## Цель проекта

Этот репозиторий является прежде всего **учебным и экспериментальным проектом**.

Цель — разобраться, из каких компонентов состоит RAG-приложение и как с помощью
Spring AI построить AI-ассистента, ответы которого основаны на документации
конкретной компании.

Сценарий обучения курьеров задаёт конкретную предметную область и позволяет
оценивать техническую реализацию не как изолированный RAG demo, а в контексте
реалистичной бизнес-задачи.

Реализация намеренно выполняется поэтапно: проект начинается с простой
интеграции LLM и постепенно дополняется retrieval, векторным хранилищем и
остальными компонентами RAG.
